# ผลตรวจสอบ

- `npm run build` ผ่าน
- Playwright Chromium: API จริงโหลดสินค้า 30 รายการและผู้ใช้ 30 รายการ, สลับครบ 3 แท็บ, ค้นหา, ผลลัพธ์ว่าง, รีเฟรช, จำลองเครือข่ายล้มเหลวและลองใหม่ผ่าน ไม่มี JavaScript runtime error
- ใช้ Playwright เพราะ Browser/IAB ตอบว่าไม่พร้อมใช้งาน
- ตรวจภาพด้วย `view_image`: design-concept.png เทียบ desktop.png และตรวจ mobile.png
- Desktop 1440×1000, มือถือ 390×844 ไม่มี horizontal document overflow; ภาพแนวคิดขนาด 1504×1046 จึงเทียบสัดส่วนที่ viewport ใกล้เคียง

## เปรียบเทียบแบบกับหน้าจอ

| จุดตรวจ | ผล |
|---|---|
| หัวเรื่องและชื่อผู้จัดทำ | ตรงกับข้อความในแบบ |
| สี | พื้นขาว ตัวอักษร navy และปุ่ม emerald ตรงตามระบบสี |
| โครงสร้าง | หัวเรื่องกลาง แท็บ 3 ตัว ค้นหาซ้าย รีเฟรชขวา และกริด 4 คอลัมน์ |
| ตัวอักษร | Noto Sans Thai กำหนดขนาดปุ่มและข้อความชัดเจน |
| รูปสินค้า | โหลดภาพ API ครบใน viewport หลังแก้การถ่ายภาพก่อนรูปพร้อม |
| Responsive | กริดเหลือ 2 คอลัมน์บนมือถือ ตารางเลื่อนแนวนอนได้ |

ตรวจข้อความเหนือ fold แล้ว: หัวเรื่อง ชื่อผู้จัดทำ และชื่อแท็บตรงตามแบบ; ตั้งใจเพิ่มหัวข้อพร้อมจำนวนรายการและปรับ placeholder ให้บอกช่องค้นหาได้ชัดขึ้น

ความต่างที่ตั้งใจเพื่อทำตามโจทย์: ใช้ชื่อ รูป ราคา และสต็อกจาก API แทนสินค้าสมมติในภาพ; แสดงตารางเต็มผ่านแท็บ แทนตาราง preview ด้านล่าง; ใช้ชื่อ อีเมล โทรศัพท์และเมืองจาก API แทนสถานะออนไลน์ที่ API ไม่มี; จำกัดพื้นที่เนื้อหา 1160px และแสดง 30 รายการต่อชุด ไม่มีการอ้างว่าตรงกับภาพแนวคิดทุกพิกเซล

รูปแบบหลักได้รับการตรวจเทียบกับภาพแนวคิดแล้ว ไม่พบเนื้อหาถูกตัดหรือปัญหาการทำงานที่ค้างอยู่
